## 3. 目标架构（二次开发）

### 3.1 设计原则（与 murmur 安全哲学严格一致）

1. **单向读出**：meme 通道与执行层严格处于神经层下游，只读 `FlyReading[]`（唤醒度 + 行为），**永不回写** connectome——这一不变量已有测试 enforced（`economy.test.ts`），本次新增代码同样遵守。
2. **Feature-flag 默认关闭**：所有新行为由 `MEME_ENABLED` / `EXECUTION_ENABLED` / `EXECUTION_REAL_SPEND` / `EXECUTION_SHADOW` 四个开关控制，出厂全关；`MEME_ENABLED=true` 而无数据源时返回安全中性值（overallHeat 0.525、NEUTRAL、零信号），等于无操作。
3. **真实资金逻辑全部集中在 `execution/`**：`economy.ts` 继续只做内部 x402 结算（本次**零改动**）；外部 swap 的唯一入口是 `ExecutionAdapter.execute()`。
4. **资金隔离**：执行钱包（`SOLANA_PRIVATE_KEY` / `EVM_PRIVATE_KEY`）与内部 x402 代理钱包（`ECONOMY_MNEMONIC` HD 派生）完全分离，永不共用。
5. **失败软化（fail-soft）**：meme 采样、D1 写入、执行日志任何故障只 `console.warn`，绝不阻断每分钟的 live cron tick（与 `archiveTick` 同一哲学）。
6. **可审计**：每次 `evaluate`/`execute` 的终态（executed / shadow / rejected / failed）全量写入 D1 `execution_log`，rejected 也记录——"为什么没交易"是调优群体决策质量的关键数据。

## 4. 本次已落地实现

### 4.1 meme 监控通道（`src/meme/`，全部新增）

**指标体系**（与附件方案逐项对应，`detectors.ts` 为纯函数、可独立单测）：

| 指标 | 含义 | 实现方式 | 输出 |
|---|---|---|---|
| `launchHeat` | 新池发射热度 | 窗口内新池数量（广度，8 个封顶）× 中位初始流动性（深度，$64k 封顶），两者 5:5 加权——过滤零流动性垃圾池刷量 | 0..1 |
| `volumeSpike` | 成交量异常 | 5m 成交量 vs 1h EWMA 基线按比例折算的倍数；1×→0，约 6×→1（√ 曲线保留 2–3× 区分度） | 0..1 |
| `holderConcentration` | 持有人集中度 | 观测集内 top-10 持仓占比的最差值；>0.45 触发 RUG_RISK 覆盖 | 0..1 |
| `smartMoneyFlow` | 聪明钱流入 | 已知聪明钱包净买入（USD），对数刻度（$1k→0.5，$32k→1） | 0..1 |
| `socialMomentum` | 社交动量 | X/Telegram 提及速率，50 次/小时封顶 | 0..1 |
| `liquidityHealth` | 流动性健康度 | 逐项扣分：未锁仓（locked<0.8）、集中度>0.45、流动性<$10k；最差值生效 | 0..1 |
| `priceVelocity` | 价格速度 | \|1h 涨跌幅\|，±80% 封顶 | 0..1 |

**融合公式**（`indicators.ts`，附件权重原样）：

```
overallHeat = launchHeat×0.25 + volumeSpike×0.30 + smartMoneyFlow×0.25 + socialMomentum×0.15 + liquidityHealth×0.05
融合温度    = Arc温度 × (1 − MEME_WEIGHT) + overallHeat × MEME_WEIGHT    （MEME_WEIGHT 默认 0.35，上限 0.5）
regime      = RUG_RISK（liquidityHealth < MEME_RUG_LIQUIDITY=0.3 或 holderConcentration > MEME_RUG_CONCENTRATION=0.45）
            | PUMP（overallHeat > 0.75）| DUMP（< 0.25）| NEUTRAL
状态机覆盖  = RUG_RISK ⇒ swarm 强制 COLD；PUMP 且 Arc 非 COLD ⇒ HOT
```

**信号评分的风险折价是乘法而非加法**（`scoreSignals()`）：rug 形态 token（未锁仓/高度集中/浅流动性）无论量能多热都会被压到 board 底部——有单测锁定该行为。

**数据源抽象**（`sources.ts`）：`fetchMemeSignals(chain, window)` 统一接口 + Provider 注册表。v0 出厂为零 Provider（离线安全、确定性）；真实 Provider（Helius / Bitquery / Birdeye / 公开 RPC 事件扫描）按 §6.1 的三步接入，**调用方零改动**。Provider 必须：只读、best-effort、fail-soft（异常吞掉返回空数组）。

### 4.2 外部执行层（`src/execution/`，全部新增）

**ExecutionAdapter（`adapter.ts`）** —— 忠实落地附件"真实可用代码骨架"：

- `evaluate()`：规则 #1 全局开关（`EXECUTION_ENABLED`）→ 委托纯函数 `evaluateRisk()`；
- `execute()`：evaluate → 拒绝（带原因）/ **shadow 优先**（`REAL_SPEND=false` 或 `SHADOW=true` 时只记录纸面成交）/ 真实路由 → **任何终态都写 D1 审计**；
- `solanaSwap()`：Jupiter v1（quote → swap 构建完整真实实现，`@solana/web3.js` 签名代码按附件以注释形式内置，装依赖后取消注释即可）；另附 **Jupiter Ultra** 变体（/order → sign → /execute，托管广播、更高落地率 + MEV 保护，生产推荐）；
- `evmSwap()`：0x v2 allowance-holder（Base 8453 / ETH 1，quote 完整真实实现）；viem 签名代码内置注释（viem 已是本仓库依赖，激活零新增依赖）；
- `ensureAllowance()`：ERC-20 approve 完整流程（读 allowance → maxUint256 approve → 等回执），对应附件 P0 项"EVM Allowance"；
- 同 token 冷却时间戳模块级持久（跨 cron 生效；隔离重启只会放松冷却、且日限额仍兜底，方向安全）。

**纯函数风险轨道（`risk.ts`）** —— 附件要求"可单独测试"的完整实现，规则顺序 = 成本顺序：

| # | 规则 | 默认值 | 说明 |
|---|---|---|---|
| 1 | 全局开关 | `EXECUTION_ENABLED=false` | 关闭时一切拒绝（在 adapter.evaluate 首位） |
| 2 | 意图健全性 | deadline 未过期、字段有界 | 畸形意图不可能钻空子 |
| 3 | 置信度下限 | `MIN_CONFIDENCE=0.45` | 群体必须"认真" |
| 4 | 日限额 | `MAX_DAILY_VOLUME_USDC=50` | 全局 UTC 日预算；剩余预算会**缩小**单笔而非放量 |
| 5 | 单笔限额 | `MAX_PER_TRADE_USDC=5` | 建议量只缩不放 |
| 6 | 仓位占比 | `MAX_POSITION_PCT=10` | 单 token ≤ 总资金 10% |
| 7 | 冷却时间 | `TRADE_COOLDOWN_SECONDS=300` | 同 token 5 分钟；只约束买入，绝不限卖出 |
| 8 | 流动性/集中度/余额 | `MIN_LIQUIDITY_USD=10000`、`MAX_HOLDER_CONCENTRATION=0.35` | 池子质量门（元数据随信号搭载）+ 资金实存 |

**Shadow 纸面环（`shadow.ts`）**：200 条有界环形缓冲（新→旧）。设计动机：**纸面结果必须出现在真实结果会出现的同一位置**，否则 shadow 模式训练不了操作者。本地/无 D1 环境下 `GET /execution/logs` 直接回落到该环。

**D1 审计日志（`log.ts` + `schema.sql`）**：`execution_log` 表（id/status/chain/token/side/amount_in/amount_out/tx_hash/reason/source_fly_ids/strength/confidence/created_at/gas_used）+ 3 索引；DDL 三处同源（schema.sql 手动执行 / state.ts 惰性创建 / log.ts 常量），幂等。

**真实组合读取（`portfolio.ts`）**：Solana（SOL + USDC）+ Base（ETH + USDC）完整读取骨架，随执行钱包 secrets 一并激活（§6.2 第 3 步）；生产需接价格源替换临时标记价。

**意图构建器（`intents.ts`）**：附件 economy diff 的移植版。策略 v1 与附件一致——高唤醒 EXPLORE/AGITATE 前 3 名对 top-2 信号投票，`confidence = min(0.95, signal.score×0.7 + avgArousal×0.3)`，<0.45 弃；**RUG_RISK 时不 mint 任何意图**。放置于 `execution/` 而非 economy（附件"改动原则"第 2 条的要求），并因 `FlyReading[]` 已含 arousal/state，**population.ts 无需新增 getAllDrives/getAllBehaviors shim**（附件在真实代码库上不必要的部分，已在 §4.4 说明）。

### 4.3 Worker 集成（`state.ts`，三处最小侵入）

1. **cron 步骤 1b**（meme 采样与融合）：Arc 温度计算**原样不动**，其后并行采样 meme 通道 → 温度融合 → regime 覆盖 → 日志行 `[DO] meme heat=… NEUTRAL signals=… fused T=…`。整个块 try/catch 包裹，失败回落原行为。
2. **cron 步骤 4c**（外部意图执行）：sub-tick 循环与 netting flush 之后，用最终 `snapshot.flies` + meme 快照构建意图 → 逐个 `adapter.execute()` → 逐条日志。零意图（默认）时该块开销为零。
3. **`GET /execution/logs`**（新端点）：有 D1 读审计表；无 D1 读 shadow 环（本地开发同等可见）；同时返回四个 flag 的当前状态，前端面板据此渲染安全标志。

另有 `config.ts`（Env 声明 + 注释）、`index.ts`（features/endpoints 清单）、`wrangler.toml`（变量块，默认全关）、`schema.sql`、`.dev.vars.example`、前端三件套的配套修改。

## 6. 技术实现路径（三阶段推进）

> 风险递增、每阶段有独立验收标准与回滚手段。阶段 0（代码落地）已完成；以下为阶段 1–3。

### 6.1 阶段 1：meme 监控增强（纯监控，零资金风险，1–2 周）

**目标**：让 meme 通道从"安全中性"变为"有真实信号"，形成多链 meme 仪表盘。

1. **接入第一个数据源（Solana 优先）**——在 `meme/sources.ts` 的 `PROVIDERS` 注册表挂 Provider：
   - **方案 A（推荐起步）**：Helius webhooks / `getSignaturesForAddress` 扫 Raydium AMM `initialize2` + Pump.fun `create` 事件 → 新池检测；`getAccountInfo` 读池子储备 → 流动性与成交量；
   - **方案 B**：Bitquery / Birdeye API 一次性拉新池 + 量能 + 持有人集中度（开发最快，成本为 API 费）；
   - Provider 只需实现 `MemeSourceProvider` 签名并注册到 `PROVIDERS.solana`，下游检测器/指标/融合/前端**零改动**；
2. **接入 Base / ETH 数据源**：Uniswap V3 / Aerodrome `PoolCreated` + `Swap` 事件扫描（公开 RPC 即可）；
3. **聪明钱 cohort**：在 D1 建 `smart_wallets` 表（地址/链/标签），`detectors.ts` 已备好净流入计算，缺的只是地址来源（可用现有 economy 钱包 PnL 榜第一批种子）；
4. **前端 meme 面板**：新池列表 + 信号热力 + `topSignals` 排行（`/market` 端点附挂 meme 快照后前端直读）；
5. **验收标准**：`POST /tick` 日志出现非零 `signals=N`；面板可见实时新池；`MEME_WEIGHT=0.35` 下融合温度对真实 meme 行情有可观测响应；
6. **回滚**：`MEME_ENABLED="false"` 一键关闭，行为回到纯 Arc 温度。

### 6.2 阶段 2：决策 → 执行桥接（shadow 起步，1–2 周）

**目标**：纸面交易跑通"quote → build → sign → send"全程，shadow 记录可分析。

1. **安装执行依赖**（Solana 侧）：
   ```bash
   npm install @solana/web3.js bs58 -w @fly/trader-worker
   ```
2. **激活签名路径**：取消 `execution/adapter.ts` 中两处注释块（Jupiter v1 的 `sign + send`、Ultra 的 `signedTransaction` 构建）与 `getSolanaPublicKey` 真实实现（`Keypair.fromSecretKey(bs58.decode(privateKey))`）；EVM 侧取消 viem 签名块与 `ensureAllowance` 调用（viem 已装）；
3. **激活真实组合读取**：`adapter.getPortfolio()` 一行切换为 `getRealPortfolio(this.env)`（`execution/portfolio.ts` 已就绪），并把 `dailyVolumeUsd`/`lastTradeAt` 改为从 D1 `execution_log` 按 UTC 日聚合（防 DO 重启重置预算）；
4. **处理两个 P0**：动态 token decimals（从 quote 返回或链上读，替换 6 位硬编码）；0x AllowanceHolder approve 流程（`ensureAllowance` 已写好，在 `evmSwap` 取消注释调用点）；
5. **配置 secrets**（wrangler secret put，见 §8）+ 准备**独立执行钱包**（切勿与 ECONOMY_MNEMONIC 同源）；
6. **纯路径验证（不广播）**：`EXECUTION_ENABLED=true` + `REAL_SPEND=false`，用真实 quote 走通"拿到报价 + 构建交易"为止（`solanaSwap` 的 quote fetch 本就是真实调用）；
7. **跑 24–48h shadow**：确认 `execution_log` 有记录、决策质量（rejected 原因分布、假想成交 vs 后续价格）可分析；
8. **验收标准**：shadow 环 + D1 稳定产出记录；无一条 `status=failed` 源自代码缺陷；portfolio 数值与链上一致；
9. **回滚**：`EXECUTION_ENABLED="false"`（或撤掉 secrets，adapter 自然全拒）。

### 6.3 阶段 3：专业化与小资金实盘（稳定后，2–4 周）

1. **小资金真实广播**：`MAX_PER_TRADE_USDC="1"`、`MAX_DAILY_VOLUME_USDC="5"`、`EXECUTION_REAL_SPEND="true"`、`EXECUTION_SHADOW="false"` 四步显式开启（缺一不可触发真实广播）；执行钱包仅充 5–10 USDC；观察 3–5 笔真实交易的 gas、滑点、实际成交价 vs quote；
2. **卖出/退出逻辑**（v2 扩展）：intent 新增 `side=sell` 路径 + 止损（`-N%` 硬止损）+ 时间退出；风险轨道对卖出保持"不限冷却"（§4.2 规则 7 已预留）；
3. **量化特征接入**：把 meme 指标作为 regime 过滤器与神经决策混合（附件阶段 3 方向）；
4. **回测**：用 D1 `execution_log` + `ticks` 历史回放影子决策，调 `MEME_WEIGHT` / 指标权重 / 置信度阈值；
5. **启用 sharding 扩容**：信号源增多或 fly 扩群时调 `SHARD_COUNT`（基础设施现成）；
6. **验收标准**：真实交易 3–5 笔全链路可审计（tx 链接可查）；日亏损/异常自动降级（P1 熔断）上线；回测框架产出第一份权重调优报告；
7. **回滚**：`EXECUTION_REAL_SPEND="false"` 即刻断真实资金（这是全局 kill switch，predictions/economy 的真实结算同样受其管束）。

## 10. 风险与注意事项

1. **附件代码的假设接口**：附件骨架假设的 `Env`/`MarketMeter`/测试框架与真实仓库有出入，已按 §4.4 全部适配——后续从附件继续搬运代码（如 Jupiter Ultra 完整版、viem 签名）时，同样先对照真实接口再落地；
2. **meme 通道的中性值污染**：无数据源时 overallHeat=0.525，开启 `MEME_ENABLED` 仍会以 0.35 权重拉偏融合温度（本次实测 0.756→0.675）。**接入真实数据源前，若不希望温度被中性值影响，可将 `MEME_WEIGHT` 暂设为 0**；
3. **冷启动基线**：MarketMeter 的 EWMA 基线依赖持续采样；本地首次 tick 温度恒 0.5 属正常冷启动行为（第二次采样起才有意义）；
4. **mock txHash 的呈现**：`JUPITER_SIMULATED_*` / `0xZER0X_SIMULATED_*` 是纸面标记，前端已识别并不渲染为可点击的 explorer 链接——绝不能让假哈希看起来像真交易；
5. **私钥纪律**：所有密钥只存在于 wrangler secrets / .dev.vars，永不进代码与 git；执行钱包与经济钱包不同源（HD 路径或助记词都不能共享）；
6. **每分钟 cron 的 CPU 预算**：执行层在零意图时开销为零；接入数据源后注意 Provider 网络调用的子请求预算（Cloudflare 上限），必要时把 Provider 移到独立 cron 或缓存一层；
7. **D1 免费层配额**：execution_log 每意图一行（rejected 也记），高频信号下注意写放大，必要时对 rejected 按天聚合；
8. **DexScreener 数据陷阱（实测踩过）**：其 `/latest/dex/tokens` 返回「watchlist token 出现在 quote 侧」的第三方交易对（实测某个无关 token 的 $9.43 池子差点触发假 RUG_RISK），以及同 token 的跨链 fork（pulsechain）对——Provider 已双过滤（未知链丢弃 + base token 必须在 watchlist 内），接入其它聚合源时注意同类问题；
9. **卖出量的 decimals 依赖**：~~卖出原始数量需要链上 decimals（P0-3），未完成前 adapter 回退到 USD×10⁶ 假设~~ **已解除（v1.2）**：P0-3 落地后实盘卖出走「台账 raw → decimals+实时价 → 硬门槛拒绝」三级，不再存在 USD×10⁶ 假设路径（buy 侧 USDC 10⁶ 是常数非假设）；
10. **中性值污染已解除**：v1.0 §10.2 提到的「无数据源时 overallHeat=0.525 拉偏温度」提醒仍适用于未配置 Provider 的场景；配置 Provider 后（本轮实测）融合值来自真实数据，无需再手动置 0 `MEME_WEIGHT`。
